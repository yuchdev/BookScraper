## Requirements

- **Flags** on the shared scrape-runtime parent (05.0/01), so both `scrape-urls` and `search` get them:
  - `--ai-fallback` (default off);
  - `--ai-fallback-max-pages N` (default `20`, `1..200`), the per-run cap on fallback **requests**;
  - `--model` with the same precedence as `detect-schema`.

  With `--ai-fallback`, a missing `ANTHROPIC_API_KEY` or an empty model ID fails at start-up, before any scraping
  (`print_log` error, exit `1`). Without the flag, the key is never read.
- **Hook point.** In `scrape_book()`, after the deterministic extraction and before building the `BookRecord`:
  1. compute the eligible fields that are still empty;
  2. if there are any and the cap isn't reached, call `extract_missing_fields()` with `page.content()`;
  3. merge the returned values.

  Leanpub's API path is not hooked; it has no selectors to drift.
- **Provenance.** `BookRecord.ai_extracted_fields: list[str]` (sorted record-field names, `[]` by default) lists
  every merged field.
  - It is written by both backends.
  - It is a **schema-version bump** only if 03.1 has already shipped schema 2 without it. Preferred path: reserve
    the field in 03.1/01 before 03.1 starts.
  - A later deterministic scrape of the same book never overwrites good data with AI data. Dedup by `hash` keeps
    the first record, so the run report flags AI-filled records for re-scrape instead.
- **Run summary.** At the end of a run, one `print_log` line gives the requests made, fields filled and dropped
  (by reason), whether the cap was hit, and the summed usage. There are no prices and no key. The 07.0 run report
  picks up the same counts when it lands.
- **Concurrency.** The fallback runs inside the existing batch of 10 concurrent tasks. The cap counter is a shared
  `asyncio`-safe counter, so a batch can't overshoot it.
